# Marts Layer Documentation (`models/mart/`)

This layer transforms clean intermediate dimensional models into aggregated, business-ready analytical data models for reporting, visualization, and grid reliability analysis.

---

## 1. Daily Balancing Authority Trade (`mart_daily_ba_trade.sql`)

Aggregates hourly inter-regional electricity exchanges up to a daily level per Balancing Authority, evaluating physical power transfers, net trade positions, and normalized dependency metrics.

### Calculations & Metric Definitions

* **Total Exports & Total Imports (`total_exports_mwh`, `total_imports_mwh`)**
  * **Calculation:** 
    * `total_exports_mwh` = `SUM(CASE WHEN value_mwh >= 0 THEN value_mwh ELSE 0 END)`
    * `total_imports_mwh` = `SUM(CASE WHEN value_mwh < 0 THEN ABS(value_mwh) ELSE 0 END)`
  * **What It Represents:** The total daily physical volume of power leaving (exports) versus entering (imports) a Balancing Authority’s grid boundaries.

* **Net Interchange (`net_interchange_mwh`)**
  * **Calculation:** `total_exports_mwh - total_imports_mwh`
  * **What It Represents:** The net daily power position of the grid operator (positive = net exporter, negative = net importer).

* **Total Trade Volume (`total_trade_volume_mwh`)**
  * **Calculation:** `total_exports_mwh + total_imports_mwh`
  * **What It Represents:** The gross physical power throughput moving across regional transmission tie-lines regardless of direction.

* **Trade Position Status (`trade_position_status`)**
  * **Calculation:** 
    * `CASE WHEN (total_exports_mwh - total_imports_mwh) > 0 THEN 'NET EXPORTER'`
    * `CASE WHEN (total_exports_mwh - total_imports_mwh) < 0 THEN 'NET IMPORTER'`
    * `ELSE 'BALANCED'`
  * **What It Represents:** A high-level categorical classification of a grid region's daily trade posture.

* **Net Trade Index (`net_trade_index`)**
  * **Calculation:** `ROUND((total_exports_mwh - total_imports_mwh) / NULLIF(total_exports_mwh + total_imports_mwh, 0), 2)`
  * **What It Represents:** A normalized trade balance score bounded strictly between **-1.00** (100% reliant on imports) and **+1.00** (100% external supplier), where **0.00** represents a perfectly balanced trade ratio.

## 2. Daily Sub-Regional Demand (`mart_daily_subregional_demand.sql`)

Aggregates utility sub-zone hourly demand up to a daily grain, providing load metrics and comparing local demand against the parent Balancing Authority.

### Calculations & Metric Definitions

* **Total, Peak, and Average Demand (`total_sub_ba_demand_mwh`, `peak_sub_ba_demand_mw`, `avg_sub_ba_demand_mw`)**
  * **Calculation:** `SUM(value_mwh)`, `MAX(value_mwh)`, and `ROUND(AVG(value_mwh), 2)` grouped by operating date and sub-zone.
  * **What It Represents:** The total daily energy consumed, the maximum hourly demand spike (peak load), and the baseline average hourly power draw for a utility sub-region.

* **Load Factor (`load_factor`)**
  * **Calculation:** `ROUND(avg_sub_ba_demand_mw / NULLIF(peak_sub_ba_demand_mw, 0), 2)`
  * **What It Represents:** A demand stability ratio bounded between **0.00** and **1.00**. A score near **1.00** indicates steady, flat electricity usage, while a score closer to **0.00** signals volatile usage with extreme peak spikes relative to average consumption.

* **Sub-BA Demand Share (`sub_ba_demand_share_pct`)**
  * **Calculation:** `ROUND((total_sub_ba_demand_mwh / NULLIF(total_parent_ba_demand_mwh, 0)) * 100, 2)`
  * **What It Represents:** The percentage share of a parent Balancing Authority's total daily grid load consumed by a specific sub-zone.

## 3. Daily Generation & Fuel Mix (`mart_daily_generation_fuel_mix.sql`)

Pivots hourly generation by fuel type up to a daily grain per Balancing Authority, categorizing energy sources into high-level environmental groups and computing penetration ratios.

### Calculations & Metric Definitions

* **Fuel & Category Volumes (`coal_mwh`, `natural_gas_mwh`, `renewable_mwh`, `carbon_free_mwh`, etc.)**
  * **Calculation:** Conditional `SUM(CASE WHEN fuel_code ... THEN generation_mwh ELSE 0 END)` statements pivoting individual fuels (`COL`, `NG`, `NUC`, `OIL`, `SUN`, `WND`, `WAT`) and grouping them into macro categories (`Renewable`, `Carbon-Free`, `Thermal`).
  * **What It Represents:** The absolute daily volume (in MWh) generated by specific fuels and energy categories.

* **Renewable Penetration Share (`renewable_penetration_pct`)**
  * **Calculation:** `ROUND((renewable_mwh / NULLIF(total_generation_mwh, 0)) * 100, 2)`
  * **What It Represents:** The percentage of daily power generation derived from clean renewable resources (Solar, Wind, Hydro, Geothermal, Biomass).

* **Carbon-Free Share (`carbon_free_share_pct`)**
  * **Calculation:** `ROUND((carbon_free_mwh / NULLIF(total_generation_mwh, 0)) * 100, 2)`
  * **What It Represents:** The total percentage of non-emitting generation on the grid, combining renewables with nuclear power.

* **Thermal Share (`thermal_share_pct`)**
  * **Calculation:** `ROUND((thermal_mwh / NULLIF(total_generation_mwh, 0)) * 100, 2)`
  * **What It Represents:** The percentage of daily power generation relying on combustible fossil fuels (Coal, Natural Gas, Petroleum).

## 4. Hourly Forecast Accuracy & Reliability (`mart_hourly_load_forecast_accuracy.sql`)

Evaluates real-time hourly operating metrics by comparing actual grid demand (`D`) against day-ahead load forecasts (`DF`).

### Calculations & Metric Definitions

* **Forecast Error & Absolute Error (`forecast_error_mw`, `abs_forecast_error_mw`)**
  * **Calculation:** 
    * `forecast_error_mw` = `actual_demand_mw - forecasted_demand_mw`
    * `abs_forecast_error_mw` = `ABS(actual_demand_mw - forecasted_demand_mw)`
  * **What It Represents:** `forecast_error_mw` shows the signed directional error in Megawatts (positive = under-forecasted, negative = over-forecasted), while `abs_forecast_error_mw` measures the absolute magnitude of the error regardless of direction.

* **Absolute Percentage Error (`ape_pct`)**
  * **Calculation:** `ROUND((ABS(actual_demand_mw - forecasted_demand_mw) / NULLIF(actual_demand_mw, 0)) * 100, 2)`
  * **What It Represents:** The relative size of the forecasting error as a percentage of real-time demand.

* **Forecast Bias Status (`forecast_bias_status`)**
  * **Calculation:** 
    * `CASE WHEN actual > forecast THEN 'UNDER FORECAST'`
    * `CASE WHEN actual < forecast THEN 'OVER FORECAST'`
    * `CASE WHEN actual = forecast THEN 'EXACT'`
    * `ELSE 'MISSING DATA'`
  * **What It Represents:** A categorical status tag defining whether the day-ahead model underestimated demand, overestimated demand, or matched real-time conditions.

* **High Ramp Risk Flag (`is_high_ramp_risk`)**
  * **Calculation:** `CASE WHEN forecast_bias_status = 'UNDER FORECAST' AND ape_pct > 5.0 THEN 1 ELSE 0 END`
  * **What It Represents:** A binary flag (`1` or `0`) identifying high-risk operating hours where real-time demand unexpectedly exceeded day-ahead projections by more than 5%, signalling a situation where emergency peaking generation was likely required.
